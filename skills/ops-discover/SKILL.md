---
name: ops-discover
description: Map the project with parallel read-only subagents and keep one visual architecture artifact - a deterministic PlantUML sequence diagram plus a legend of real file paths. Use before planning, at init, and after a change is archived.
disable-model-invocation: true
argument-hint: [--refresh] [--scope <paths>] [--onboarding]
---
ROOT = $CLAUDE_PLUGIN_ROOT if set, otherwise ~/.ai-developer-ops. The renderer lives in the tool, not in the analysed project: always call `python3 "$ROOT/scripts/render_arch.py"` (explicit interpreter, like `bash "$ROOT/scripts/init.sh"` in init; the file is not marked executable). Never edit the analysed project outside `docs/`.

1. Recon in parallel read-only subagents (Claude: `Explore`; Codex: `explorer`), one per area, five in one turn: entry points; components and their responsibilities; data flow; external integrations; background jobs. If the harness caps concurrency, batch them - every area must be covered exactly once. Retry a failed area once; on a second failure stop, name the area, and write nothing. A partial model would read as an architecture that lost a piece.
2. Write `docs/architecture.model.json` - facts only, no prose. Components: `id` `label` `layer` `path`. Flows: `id` `label` `kind`. Interactions: `flow` `from` `to` `verb` `op` `seq`.
   - `layer` is one of exactly seven: `actor`, `ui`, `api`, `service`, `repository`, `data`, `integration`. The closed set is what makes box order deterministic; nothing else is accepted.
   - `id` matches `^[A-Z][A-Za-z0-9]*$`, derived from the component name, and must not end in `Group` (reserved for aggregates).
   - Participants are components - API, services, repositories, database, queue, cache, external integrations, UI. Never a class, never a function.
   - `path` must exist in the repo; a file or a directory. Only an `actor` has `path: null`, and only an actor may.
   - `seq` is an integer, stepped by 10 so a later insertion needs no renumbering. Exactly one flow has `kind: "main"`.
   - `title`, `label`, `verb` and `op` allow letters, digits, space and `- _ . / ( ) : ,` only. Anything else is rejected rather than escaped, because these strings reach both PlantUML and Markdown.
3. Render: `python3 "$ROOT/scripts/render_arch.py" validate --model docs/architecture.model.json` first and fix what it reports, then `python3 "$ROOT/scripts/render_arch.py" all --model docs/architecture.model.json --puml-out docs/architecture.puml --md-out docs/ARCHITECTURE.md --scope "<what this run covered>"`, adding `--preserve docs/architecture.puml` whenever that file already exists. Then `make docs` for the SVG and `make docs-fresh` to confirm. Ordering, layer grouping, aggregation past twelve participants and the legend are the renderer's job, not yours - do not hand-write `.puml`.
4. `--refresh`: a component belongs to the run when its `path` is at or under a `--scope` path; an interaction belongs to its `from`. In-scope entries are replaced by what recon found, out-of-scope entries are left byte-for-byte alone. An interaction left pointing at a component that no longer exists is dropped and listed in the report. A flow left with no interactions is dropped; if that would empty the `main` flow, stop with "scope too narrow" and write nothing. A rename is a removal plus an addition - component identity is not tracked across `id` changes. `--scope` with no existing model is allowed; say plainly in the report that the result is not the whole architecture.
5. Manual additions in `.puml` carry a trailing `' manual` comment and survive every refresh. One line each, and only a message (`A -> B : text`), a note (`note left of X : text`) or a full-line comment; a hand-added `participant`, `box`, `group` or `activate` is refused. A manual line whose section or participant is gone comes back before `@enduml` commented out under `' manual-orphan`, and the report names it. To revive one, move it back and change the marker to `' manual`.
6. `--onboarding`: also write `docs/ONBOARDING.md` - local run, the order to read files in, up to five execution paths step by step naming participants from the legend (at least one), and five to ten questions answered with a path to a real file. Budget 200 source lines. With fewer than five real flows, write the ones that exist and say in the report how many the repo has. Without the flag this file is neither created nor touched.
7. Report: the stack and the detected build, test, lint and run commands (`init` needs these to fill its Makefile and AGENTS.md TODOs); every dropped interaction and orphaned manual line; the participant count and any aggregate; anything recon could not resolve. Never claim a diagram is current without `make docs-fresh` passing.
